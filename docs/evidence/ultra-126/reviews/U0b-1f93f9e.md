## Findings

- `packages/skill-summon/src/summon/session.ts:955` - **warning, blocking**: Index updates are serialized only by an in-memory queue. Two separate server processes starting with the same harness ID can both read the same index entry, then atomically rename different updates over it; the last rename loses the other root. Similarly, a concurrent removal can erase a newly recorded root. Once the lost root’s owner dies, bounded lookup cannot discover it, so resume creates a fresh session and loses automatic campaign continuity. The concurrency test uses two calls in one process and therefore cannot expose this race. Serialize each index key’s read-modify-write across processes, or use a representation that permits independent atomic root entries, and add a cross-process regression test.

## Findings

- `packages/skill-summon/src/campaign/store.ts:207` — **critical**: The append queue is per `CampaignStore` instance, while the disk comparison and append are not atomic across instances. Two stores loaded from the same root can both pass `#assertDiskMatchesMemory()` before either writes, then append entries with the same sequence number. Both calls can succeed, but the persisted trace fails verification on reload. Serialize the comparison and writes with a shared per-root exclusion mechanism, and test simultaneous appends from independently loaded stores. The existing stale-writer test is sequential and does not cover this interleaving.

- `packages/skill-summon/src/campaign/store.ts:281` — **warning**: A trace can legitimately load without `evidence.jsonl` when a trusted `authorize` callback supplies authority, as the test explicitly demonstrates. A subsequent append creates an evidence file containing only the new sequence number; its first line is not sequence zero, so the next load fails closed despite the append having returned success. Either reject append before modifying disk when historical evidence is absent, or safely construct complete bound evidence before allowing the append. Add a load-with-callback, append, and reload test.
