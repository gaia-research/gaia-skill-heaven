D-009 unit: U3, U9 A (Opus orchestrator)
2026-11-16
problem
Security limit raised by a side agent and confirmed against P1's own method. MCP elicitation (channel 1) delivers whatever is typed into the terminal to the server. In P1, a worker agent answered the elicitation prompt with herdr pane send-text, and the server received a normal accept that nothing distinguished from a person. Any process that can write to the terminal can do the same: every lane here (herdr socket), and a Skill Ultra session's own model when it has a shell tool and its terminal sits in herdr or tmux (HERDR_SOCKET_PATH / TMUX in its environment); for example, a parallel shell call issued beside the campaign call.
options
  • Drop channel 1
  • Keep channel 1, state plainly what it is not, disclose terminal multiplexing at decision time, and require the real proof decision to be made where no agent can inject input
  • Invent a nonce or challenge (rejected: an agent can read the pane as easily as type into it)
selected
Keep channel 1 as the selected channel (it still keeps the model out of the tool path, and no channel on this harness authenticates a person), but: (1) the P1 record and the U3 evidence say that channel 1 is terminal input, not authentication, the same class of boundary as channels 2 and 3 and the steering brand; (2) U3's operator path records, with each operator entry, an attribution field 'terminal-input, unauthenticated' plus whether the server's environment shows a multiplexer (HERDR_ENV/HERDR_SOCKET_PATH/TMUX), and the decisions render discloses it; (3) U9's real operator decision is made by the founder in a terminal no agent controls (outside herdr and tmux, or a pane whose socket no running agent can reach), and PROOF.md says which; (4) no test fixture keystroke is ever recorded as a person's decision.
reason
Honest disclosure of a real boundary without inventing authentication the harness does not provide; it preserves invariant 4 (agent text cannot manufacture operator authority) in the proof, where it matters.
authority

D-010 unit: U3 A (Opus orchestrator)
2026-11-16
problem
Implement FD-11: safeguarded default, an unadvertised opt-in for multiplexed approvals, and a probe of auto mode's classifier.
options
  • Env-flag opt-in
  • Config-file opt-in
  • CLI-flag opt-in
selected
(1) Default: an elicitation accept grants operator authority only when the server's environment shows no multiplexer (HERDR_ENV, HERDR_SOCKET_PATH, TMUX). Otherwise the decisions step fails closed at DECISIONS with a plain message. (2) Advanced opt-in: the person sets an env var themselves before launching the session (name fixed in vocabulary.ts, e.g. SKILL_ULTRA_MULTIPLEXED_DECISIONS=accept-risk). It is documented only in an advanced or evidence note, never in the README, site, command help or skill text. Under opt-in, every operator entry records attribution 'terminal-input, unauthenticated', multiplexed:true and optIn:true, and the decisions render and status show it. (3) Safeguard inside the opt-in: the elicitation form asks the person to type the charter's short digest, shown in the prompt, so a blind or replayed injection does not match. This is disclosed as friction, not authentication. (4) Probe P1d measures auto mode's classifier against a self-approval attempt, and U3 records the result per mode.
reason
Matches FD-11: a safe default for ordinary users, nothing advertised, and advanced multiplexer users keep working. Terra's critical finding is answered by the default fail-closed plus an explicit, recorded, person-set opt-in.
