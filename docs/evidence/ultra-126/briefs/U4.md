## Deliver

- `packages/core/src/campaign/units.ts`: work-unit states `ready → active →
  verifying → done`, `verifying → recovering → active`, `recovering → reopened →
  active`, `→ needs-human`, `→ blocked`. Pure.
- `queue.ts`: `next` ordering is dependency order, then charter phase order,
  then a stable tie-break. Regrouping after the decisions step writes a checkpoint entry.
- `receipts.ts`: a verify receipt = command + output digest + exit status, labelled
  `attested` (PR-5). A unit closes **only** on a receipt whose command the charter
  names (INV-U15). No receipt text claims the work is good.
- The steering adapter, owned by the engine: verify failure → `behavioral-failure`,
  verify pass → `behavioral-recovery`, through `stepSteering`. The working rung
  comes from steering. **No retrieval score, margin or `noMatch` reaches it**
  (INV-U3, K4). Add a test that constructs every retrieval-derived value and
  proves none can become a steering event.
- `ops/next.ts`, `ops/report.ts`, `ops/checkpoint.ts`. Report: RECOVER until the
  charter's recover bound, then REOPEN until the reopen bound, then CONVERGENCE.
  A retrieval refusal is never read as a reason to explore harder.
- CLI: `--campaign-replay-receipts <trace>` re-runs recorded commands **only when
  explicitly invoked by a person**, upgrading matching receipts to `replayed`.
  It never runs automatically.

## Tests

Recover → reopen → convergence at the charter's bounds, including bounds of 0. A
150-unit synthetic sequence (seeded generator, no `Math.random`) replays
byte-identically. A unit closes only on a charter-named receipt. A blocked unit
does not stop independent units (PR-9). The working rung comes from steering
(assert on the steering trace). The retrieval-isolation test above. The replay CLI
upgrades a matching receipt and leaves a mismatched one `attested`.
