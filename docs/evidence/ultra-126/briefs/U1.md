## Deliver

- `packages/skill-summon/src/campaign/tool.ts`: the single `campaign` tool,
  dispatching on `op`. Unknown op → structured refusal; nothing is thrown to the client.
- `ops/open.ts`: the goal contract (goal, work universe, repositories, acceptance
  commands, human-only operations, stop conditions) stored as structured state
  through U0b's store. RECON follows.
- `ops/recon.ts`: `gaps: string[]` chosen by the agent. Exactly one
  `preview: true` call per gap through the existing deterministic ranker (FD-2: no
  model call in the router). Per gap, record candidates (cards), refusal or `noMatch`,
  source freshness, installability, lane, and the Arbor and Graph lenses, each with
  its explicit absent state when unknown. Writes a `skill-heaven/campaign-recon/v1`
  record into the trace. **Materializes nothing** (INV-U2, K2). A refused gap is
  recorded and is not an error, and it is never a signal to explore harder.
- `ops/status.ts`: current state and digest.
- Every campaign result carries a short state digest (plan §2 rule 4). Keep the
  digest builder in one function; U5 reuses it for summon results.
- Register the tool in `mcp/server.ts` **behind a server option that the bundled
  binary does not set** (decision D-002; U3 enables it). Rebuild `build:mcp` and
  confirm the bundled server does NOT list `campaign`.

## Tests

Nothing is written under the session `skills/` directory during recon (assert on
the filesystem); `zero_cuts=all` refuses recon; a refused or `noMatch` gap is
recorded and recon still succeeds; Arbor and Graph lenses report their absent state
when data is missing; the bundled-binary tool list is unchanged (no `campaign`);
authority regression green.
