## Implementation and API

- `CampaignStore.load(sessionRoot, options?)` and `append(event)` in `packages/skill-summon/src/campaign/store.ts`: append-only `campaign/trace.jsonl` rows, separate position/event/record-bound `campaign/evidence.jsonl`, and `campaign/status.json` via U0a `toControllerStatus`. Loading uses `replayCampaign` and `verifyCampaignRecord`; invalid history becomes `FAILED_SAFE`, never rewritten/repaired. Status is refreshed from verified fold, including failed-safe projection. An absent campaign stays write-free.
- Strict shared trace/evidence format helpers in `packages/core/src/campaign/trace-format.ts`, exported through campaign index for store and CLI parity.
- Single `HARNESS_SESSION_ID_ENV_VARS` constant includes `CLAUDE_CODE_SESSION_ID`; manifest records harness ID. Automatic resume scans only validated disposable direct-child roots and requires matching ID + proven-dead PID. Explicit roots obey ID/dead-PID policy when harness ID exists; legacy explicit-root no-ID reuse remains. Reattachment updates PID and preserves root/skills/campaign paths. Fork/unmatched ID gets fresh root and no campaign.
- Reaper folds verified trace (never trusts status.json) and uses approved charter `sessionRetention` in hours for dead executing/convergence roots, anchored to a confined `campaign/pause.json` boundary bound to PID and verified record digest. It conservatively records the first dead-PID observation with injected `now`, never renews a matching boundary on repeated reaps, and clears it on reattach. Invalid regular pause artifacts are conservatively re-established once; symlink/nonregular/unconfined pause paths preserve the approved campaign without touching targets. Both real and dry-run retention use read-only verified fold independently of derived status; dry-run writes no campaign/status/pause artifact. Uncertain verification or boundary I/O preserves roots, never masquerades as no decided window. Unapproved/missing/corrupt/terminal campaign uses existing TTL unchanged; no compiled pause-window default. Injected-clock tests cover old long-lived sessions, exact boundary and lifecycle reset; no sleeps.
- Controller status consumer constant is `/v1`; new phases accepted and reported progress rendered. Console reads exact bounded confined optional status; valid pre-summon campaign renders without summon-log.jsonl. Invalid status never becomes a campaign claim. Reported campaign status never fabricates an observed Ultra command, changes reading/source, or overrides selectedFrom; rendering and Console scope distinguish reported progress from observed selection.
- Standalone `--campaign-verify <trace>` supports actual JSONL plus serialized U0a record JSON, returns nonzero on malformed/tampered/un-evidenced privileged histories; `--campaign-explain <trace>` renders every transition kind. Neither flag launches a harness or grants live authority.
- MCP, status and all affected Console bundles rebuilt. Server SIGINT/SIGTERM code was already root-preserving (`server.close()` only), so no server-entry source edit or harness reprobe was needed.

## Security, limitations and dependencies

Campaign content reads and writes are confined through `assertConfinedPath`, including trace/evidence and status projection writes, with symlink/outside-root regressions. Read-only retention folding does not inspect derived status when trace exists; when trace is missing, orphan status/evidence detection uses non-following `lstat` only, not content reads. Session adoption checks physical disposable-root namespace and manifest/PID. No user-global configuration, settings or skills writes, hooks, uploads, daemon, runtime dependency, live campaign tool registration or availability claim. Ultra stays provisioned.

Sibling evidence protects trace-only changes, not arbitrary coordinated writes to every session artifact; it is not a signature or human authentication. External `authorize(event,index)` / `expectedRecord` seams support independently retained trust. U3 owns real operator provenance. Per-instance appends are serialized and stale on-disk history refused; no OS cross-process lock is claimed. PID reuse and same-user arbitrary host/filesystem execution remain trust limitations. The pause boundary uses the first dead-PID reap observation, not exact process-exit time, so an unobserved exit may conservatively retain the root longer; repeated reaps do not extend its decided window. Measured Claude Code 2.1.325 P2a facts were used without reprobe.

No in-house Skill Heaven plugin validation is claimed from native development tools/tests. No plugin-scope actionable dogfooding feedback arose; no feedback issue was filed.
