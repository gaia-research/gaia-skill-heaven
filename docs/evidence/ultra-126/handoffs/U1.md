## Implementation summary

- **Single `campaign` tool (`tool.ts`) & D-002 gate (`mcp/server.ts`):** Dispatches on `op` (`open`, `recon`, `status`). Unknown operations, operator verbs, and malformed MCP inputs return structured refusals (`isError: true`, `structuredContent` with `refused: true`, `error`, and `digest`) and never throw to the client. Registered in `createSkillSummonMcpServer` behind `enableCampaignTool?: boolean` (default `false`), leaving the rebuilt bundled binary (`plugins/skill-heaven/mcp/skill-summon.mjs`) listing only `["summon"]`.
- **Goal contract & `open` (`ops/open.ts`, `store.ts`):** Validates `goal`, `workUniverse`, `repositories`, `acceptanceCommands`, `humanOnlyOperations`, and `stopConditions`, binds `goalSha256` directly into the `open` event in `trace.jsonl` and `artifactSha256` in `evidence.jsonl`, and commits `goal.json` + trace + evidence via a two-phase staging protocol.
- **Deterministic reconnaissance & lenses (`ops/recon.ts`, `store.ts`):** Runs exactly one `summon(..., { preview: true, decision: "classic", live: false })` call per gap, writing nothing under `<sessionRoot>/skills/`. Records candidate cards (`cardRef`, `id`, `name`, `card`) and separate lenses (`retrieval`, `lane` with `convergenceOnly: true` on `human-led`, `freshness`, `installability`, `arbor`, `graph`), each with explicit `absent-*` states when unknown. Refused and `noMatch` gaps are recorded as gap outcomes (`"No capability found"`) without failing `recon` or triggering steering events. `zero_cuts=all` refuses `recon` while reporting the actual readable campaign state (or `UNAVAILABLE`). Every recon run is preserved by `reconId` in `recon.json` and cryptographically bound to `trace.jsonl` (`recon-sha256:<reconId>:<sha256>` covering `schema`, `reconId`, `gaps`, `findings`, and base `citations`).
- **Status & single digest builder (`ops/status.ts`):** `buildCampaignDigest` produces the deterministic state digest attached to every campaign tool result (and reusable by U5 via `readSessionCampaignDigest`). In prose `text`, `UNARMED` is rendered as `IDLE` so `authorityHits` is `[]` across all 11 campaign states.

## Security considerations, known limitations and outstanding issues

- **Security:** All campaign artifacts (`goal.json`, `recon.json`, `.goal.stage.json`, `.recon.stage.json`) are confined to `<sessionRoot>/campaign/` via `assertConfinedPath` and regular-file `lstat` checks, written via atomic `wx` temp + `rename`, and bound to `trace.jsonl` (`goalSha256` and `recon-sha256:<reconId>:<sha256>`) and `evidence.jsonl` (`artifactSha256`). Any tampering, rollback to a stale recon record, or deletion of `goal.json` / `recon.json` fails closed into `FAILED_SAFE`. All rendered card/finding/digest text is escaped and passes `authorityHits` with zero matches; `"ratify"` appears nowhere.
- **Known limitations:** U1 implements `open`, `recon`, and `status` only; `propose`, `next`, `report`, and `incident` remain structured refusals until U3, U4, and U6 wire them. `campaign` remains gated off by default in the bundled MCP binary until U3 lifts D-002. Ultra copy remains `"provisioned"`.
- **Dependency changes:** None.
- **Outstanding issues:** None.
